# UI ownership

Scope: shared presentation and reported maintenance case management. Flask routes own authorization and validation; `backend/storage/case_store.py` owns durable lifecycle transitions. Product context: the user's October 10 decision, `README.md`, and the bot's reporting and closing flows.

| Capability | Canonical owner | Contract |
| --- | --- | --- |
| Period filters | `static/js/core/state.js` | Existing period handlers retain API semantics; leaderboard period changes reset ranking pagination and expose pressed state. |
| Filter presentation | `static/css/core/kurtex-v23.css` | One shared segmented style across existing filter groups. |
| Select/Listbox | `static/js/core/custom-select.js` | Preserve existing shared select enhancement; no replacement introduced. |
| Scrollbar | `static/css/core/kurtex-v23.css` | Global inherited theme styling, with system forced colors. |
| Leaderboard | `static/js/features/views.js`, `static/css/core/chrome.css` | Metrics precede a contained performance report whose toolbar owns period and rank-by filters. Ranking uses a comparable table and existing paging/calculations; insights and theme-aware charts share the selected period. Rank-by uses the shared select owner. |
| Theme | `static/js/core/state.js`, dashboard CSS tokens | Stored preference controls document theme; legacy aliases resolve to canonical surfaces. |
| Home briefing | `static/js/features/home.js`, `/api/home/briefing`, `static/css/features/home.css` | Read-only briefing requires Cases permission. Chicago date boundaries define reported and closed-today counts; reports use the shared maintenance predicate. Attention flags high priority, missed, unassigned and maintenance reports open at least 24 hours, with six rows and an exact count. Matching Cases filters reuse the same predicates and ordering. Active maintenance opens Workspace. No status transitions are introduced. |
| Home activity and findings | `home.js`, `/api/home/briefing`, existing `/api/home/ai-summary` | Eight latest recorded reports, openings, assignments, closures, edits and notes link to the existing case modal. Do not infer an event timestamp from current status. Case IDs and user content are escaped. Optional Intelligence findings refresh at most every five minutes automatically, with manual retry and a separate checked timestamp. Failures retain previous data and identify unavailable refreshes. No AI wording is required for the factual case briefing. |
| Home customization and shortcuts | `static/js/features/layout.js`, `/api/preferences/overview`, existing navigation and Workspace form | Add attention to the shared widget catalog; preserve custom orders and visibility and migrate the former default. Customize Home exposes ordering and hiding without mandatory drag controls. Quick actions respect available pages and reuse canonical destinations, form validation and save behavior. Metrics remain individually hideable. List updates defer while keyboard focus is inside the list. |
| Intelligence layout | `analytics.js`, `chrome.css`, existing `/api/kurtex_intelligence` | Four summary cards precede the findings toolbar and finding cards. Filters expose pressed state. Refresh disables duplicate actions and ignores superseded results; failure preserves cached findings with inline feedback. Existing evidence and lifecycle handlers remain authoritative. |
| Parts Manual | `views.js`, `chrome.css`, existing parts catalog | Visible category buttons reuse the existing category predicate and expose pressed state. Search has a clear action, IME-safe input/Enter handling, and stale web responses cannot overwrite a cleared search. No total-parts badge or zero count label. Results and reference content follow the shared header and use natural document height. |
| My Profile | `views.js`, existing `/api/my_profile`, shared settings dialog | Identity and role remain server-owned and read-only. All-time statistics and today/week cohorts use existing API fields. Local search/status controls cover the ten recent records only and preserve their values on refresh. Case actions reuse the canonical case modal; preference shortcuts reuse the settings dialog. Initial failure offers Retry; background failure retains data. Focused case rows defer polling updates. No new account or case writes. |
| Agent directory | `static/js/features/agents-v23.js`, `/api/agents`, `/api/agent` | Server-owned identity, role, statistics, status/search filters and chronological sort; 20 cases per page. Ignore stale responses when selecting another agent. |
| Agent activity presentation | `static/js/features/agents-v23.js` | Five compact metrics without average response; columns Driver, Group, Case / Unit, Reported, Status, Actions. Clear search returns focus to its input. |
| Case Workspace | `static/js/features/case-workspace.js`, `/api/cases?filter=workspace` | Only maintenance reports with open/assigned/reported status and no close timestamp. Independent filters for query, status, priority, equipment, sort and grouping. Closed reports remain in the unchanged Cases history. New reports appear through existing polling. Counts describe loaded reports. |
| Report writes | `/api/workspace/cases`, `backend/storage/case_store.py` | Current registered membership, Cases page permission and session CSRF token are required. Agents manage their own reports; super admins and developers manage all. New reports are assigned to the creator. Create retry keys and repeated closes are idempotent. Revision conflicts reject stale edits. Save failures preserve entered values and never claim success. |
| Report lifecycle | `case_store._close_record`, `case_store.save_maintenance_report` | Workspace and Telegram share the Done transition and timing fields. Close preserves report notes and appends actor history. Report submission saves fields under the same lock and cannot reopen a case closed concurrently. No deletion or Telegram dispatch is performed by Workspace writes. |
| Forms and confirmation | Shared `.modal-overlay` shell, `custom-select.js`, `case-workspace.js` | New/edit/note forms use labeled fields and native required validation. Close requires an app-owned confirmation explaining retention. Pending writes disable controls; errors retain the form. Escape, focus trapping and focus return reuse the shared modal owner. |
| Full case | `case-workspace.js` | Open full case stays within Workspace and uses the same selected report, authorization and actions. Back preserves board query, filters and grouping. Description, notes, history, attachments and related loaded reports contain real data only. |
| Retained case history | `views.js`, `case-workspace.js` | The existing Cases detail modal displays retained report comments, workspace notes and actor history through the same renderers used in Workspace. Closed reports remain searchable with status Done. |
| Global clock | `static/js/core/app.js` | Preserve America/Chicago time, date, and connection status in the shared main top bar. Workspace hides the right side of that bar. |
| Shell and filter summaries | `static/js/features/ui-refinements.js`, `static/css/core/chrome.css` | Missed Cases is the shared shell baseline: consistent sidebar, main gutters and one top bar in document flow. Operational tabs use a single title with clock and notifications; Workspace shows only its title. Home retains Report/Print/Export/Refresh and its welcome layout. Missed Cases search follows the shared title inside its results panel. Case history search, period, status and native date controls share an aligned toolbar above the table. Flex-based legacy pages keep the shared title row before content. Search queries remain in memory; workspace view/group persist. |
| Notifications | `static/js/features/notifications.js`, `static/css/core/chrome.css` | Counted All/Unread/Alerts filters have pressed state and appear only when updates exist. Empty inbox hides filters, mark-all and footer actions. Loading, failure, cached data and retry are explicit. Case links and mark-read actions are separate native buttons; pending reads disable duplicate actions and failed reads preserve unread state. Latest notification refresh wins. Local notifications, dismissed IDs and watch snapshots are scoped per account; repeated local events are suppressed. Case watching requires Cases permission. Bell expanded state tracks opening, outside dismissal and Escape; Escape restores focus. Existing preferences remain authoritative. |
| Workspace board navigation | `case-workspace.js`, `features/workspace.css` | Mouse drag pans the board after a movement threshold and suppresses the following click; ordinary clicks open cases. Previous/next controls and focused-board Left/Right/Home/End keys navigate horizontally. Trackpad movement stays native; wheel scrolling honors scrollable columns before horizontal panning. Reduced motion disables smooth arrow scrolling. Background board renders defer during panning. No assignee or lifecycle changes are made by navigation. |
| Mobile workspace inspection | `static/js/features/case-workspace.js` | Non-modal full-width in-page inspector replaces board content on phones; close restores the matching case button and page scroll. Filters stay intact. Header and actions remain outside the scrolling detail body. |
| Theme compatibility | `static/css/core/theme.css`, `static/js/core/state.js` | HTML data attribute and legacy body class stay synchronized; high-specificity Home surfaces follow canonical dark tokens. Desktop workspace opens its first available case once; phones wait for a selection. |

Verification for this change is limited to source inspection at the user's request: no local tests, app startup, browser checks or audits were run. Runtime visual fidelity, keyboard behavior and write workflows remain unverified.
